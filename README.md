## Общее описание

Данное приложение представляет собой графический эмулятор терминала UNIX-подобной системы, разработанный на языке **Java** с использованием библиотек **Swing** и **AWT**. Эмулятор взаимодействует с виртуальной файловой системой (VFS), загружаемой из JSON-файлов, и выполняет все операции изменения структуры исключительно в оперативной памяти. Проект разработан в рамках дисциплины «Конфигурационное управление» (практика, Вариант 16).

Программа демонстрирует применение многопоточности (паттерн **Producer-Consumer**) и функциональных интерфейсов Java, а также корректное взаимодействие с **Event Dispatch Thread (EDT)** через `invokeLater` и `Runnable`.

## Поддерживаемые команды

| Команда | Описание |
|---------|----------|
| `ls`    | Отображение содержимого текущей директории VFS |
| `cd`    | Переход в другую директорию (или в корневую, если аргумент не указан) |
| `pwd`   | Вывод абсолютного пути текущего рабочего каталога |
| `clear` | Очистка экрана терминала |
| `exit`  | Закрытие окна и корректное завершение работы эмулятора |
| `help`  | Вывод списка доступных команд |

## Виртуальная файловая система

VFS построена на основе JSON-файлов. Поддерживаются следующие конфигурации:

- `vfs_minimal.json` — минимальная структура.
- `vfs_nested.json` — вложенная структура каталогов.
- `vfs_source.json` — исходная структура, используемая по умолчанию.

Все изменения (перемещение, переименование, смена владельца) выполняются только в оперативной памяти и не затрагивают исходные файлы.

## Архитектура и многопоточность

Обработка команд реализована через паттерн **Producer-Consumer** с использованием `LinkedBlockingQueue`:

- **UI (Producer)** — помещает введённую пользователем команду в очередь.
- **CommandInterpreter (Consumer)** — извлекает команду из очереди, сопоставляет её с зарегистрированными обработчиками и выполняет действие.
- Результат выполнения передаётся обратно в UI через `invokeLater` для безопасного обновления интерфейса в главном потоке.

### Параметры конфигурации

Параметры запуска передаются через файл `config.yaml`. Пример конфигурации:

```yaml
vfs_path: vfs_source.json
```

## Структура проекта

```
University-Terminal-Emulator/
├── src/                            # Исходный код на Java
│   ├── Activator.java              # Точка входа
│   ├── UI.java                     # Графический интерфейс (Swing/AWT)
│   ├── CommandInterpreter.java     # Обработчик команд (Consumer)
│   ├── CommandContext.java         # Контекст выполнения команд
│   ├── *Command.java               # Реализации команд (ls, cd, pwd, и т.д.)
│   ├── Vfs.java                    # Виртуальная файловая система
│   ├── VfsLoader.java              # Загрузка VFS из JSON
│   └── ...
├── tests/                          # Модульные тесты (JUnit)
├── config.yaml                     # Конфигурация
├── run.sh                          # Скрипт запуска (Linux/macOS)
├── vfs/                            # Файлы виртуальной файловой системы
|   ├── vfs*.json                      
└── README.md
```

## Сборка и запуск

### Linux / macOS

```bash
chmod +x run.sh
./run.sh
```

### Запуск тестов вручную

```bash
java -cp "src:tests" org.junit.runner.JUnitCore <имя_тестового_класса>
```

Тесты расположены в директории `tests/`.
